  - q: "What is the difference between preventive and predictive maintenance?"
    a: "Preventive maintenance is done at fixed intervals, such as every 3000 running hours, whether the equipment needs it or not. Predictive maintenance uses the measured condition of the equipment to estimate when it will fail, so work is done only when needed, just before failure. This reduces both unplanned breakdowns and unnecessary servicing."
  - q: "How much data is needed to start predictive maintenance?"
    a: "Anomaly detection can start with a few weeks of data from normal operation. Failure classification and remaining useful life models need recorded examples of failures, ideally many of each type, which can take years to collect. Most programmes start with condition monitoring and anomaly detection, then add supervised models as failure history builds."

<Key title="Short answer">

**Predictive maintenance** with machine learning uses sensor data such as vibration, temperature, current and pressure to detect early equipment degradation and forecast failures. Anomaly detection flags abnormal behaviour, failure classification predicts which fault is coming, and remaining useful life regression estimates time to failure, so maintenance is scheduled just in time.

</Key>

Maintenance strategies have evolved from fixing machines after they break (**reactive**), to servicing them on a fixed schedule (**preventive**), to servicing them based on measured condition (**predictive**). Machine learning makes predictive maintenance scalable, because it can watch thousands of signals across hundreds of assets and learn patterns that are hard to capture with fixed alarm limits.

### 1. Sensors and data

The most useful signals for rotating equipment are:

- **Vibration:** accelerometers reveal imbalance, misalignment, looseness and bearing defects, often weeks before failure.
- **Temperature:** bearing, winding and process temperatures show friction, overload and cooling problems.
- **Motor current:** current signature analysis detects broken rotor bars, load changes and some mechanical faults.
- **Process variables:** pressure, flow and level, measured by plant [process instruments](https://www.instrumentationblog.in/category/process-instrumentation/), show pump wear and fouling.
- **Oil analysis and acoustic emission** for gearboxes and slow speed bearings.

Data also comes from the control system, historians and the maintenance management system (CMMS), which records failures and repairs. These records are the labels for supervised models.

### 2. Feature extraction

Raw high frequency signals are summarised into features over windows of time:

- **Time domain:** root mean square (RMS), peak, crest factor, kurtosis and skewness.
- **Frequency domain:** a fast Fourier transform (FFT) shows energy at shaft speed and its harmonics, at gear mesh frequencies and at bearing defect frequencies.
- **Trends:** rate of change, rolling means and deviation from a baseline.
- **Context:** load, speed and ambient temperature, so the model does not mistake a load change for a fault.

The RMS of a vibration signal with N samples is:

$$
x_\text{RMS} = \sqrt{\frac{1}{N}\sum_{i=1}^{N} x_i^2}
$$

Kurtosis is particularly sensitive to the sharp impacts of early bearing damage: a healthy signal has kurtosis near 3, and values well above that suggest impulsive faults.

## Machine learning approaches

### Anomaly detection

An [unsupervised](/ai-data-engineering/supervised-vs-unsupervised-learning/) model learns what normal looks like and flags deviations. Methods include statistical limits on features, isolation forests, one class SVMs and autoencoders, which are [neural networks](/ai-data-engineering/how-neural-networks-work/) that reconstruct normal data well and abnormal data poorly. Anomaly detection needs no failure history, which makes it the usual starting point.

### Failure classification

A supervised classifier predicts whether a failure will occur within a horizon, such as 7 or 30 days, or which failure mode is developing. Gradient boosted trees and random forests work well on engineered features. The challenge is **class imbalance**: failures are rare, so careful labelling, resampling or class weighting, and precision and recall based evaluation are needed.

### Remaining useful life (RUL)

A regression model estimates the time or cycles left before failure. Approaches range from fitting degradation curves to a health indicator, to deep learning on sequences of sensor data. The NASA C-MAPSS turbofan dataset is a widely used benchmark for RUL research.

| Approach | Question answered | Data needed | Typical methods |
| --- | --- | --- | --- |
| Anomaly detection | Is this behaviour abnormal? | Normal operating data | Isolation forest, autoencoder, statistical limits |
| Failure classification | Will it fail within N days? Which fault? | Labelled failure history | Random forest, gradient boosting |
| RUL regression | How long until failure? | Run to failure histories | Degradation models, LSTM, CNN |

## Implementing predictive maintenance

1. **Select assets** by criticality and downtime cost, using a failure mode and effects analysis.
2. **Check the instrumentation:** add sensors where key failure modes are not measured.
3. **Build the data pipeline** from edge devices and historians to an analytics platform, as described in [ETL vs ELT](/ai-data-engineering/etl-vs-elt/).
4. **Start with condition monitoring and anomaly detection**, reviewed with maintenance experts.
5. **Record failures carefully** in the CMMS: date, asset, failure mode and cause. Good labels unlock supervised models.
6. **Integrate alerts into work processes** so a warning becomes a planned work order, not an ignored email.
7. **Measure results:** unplanned downtime, maintenance cost, false alarm rate and mean time between failures.

## Common pitfalls

- **Too many false alarms** make technicians ignore the system; tune thresholds with their feedback.
- **Ignoring operating context** such as load and speed changes.
- **Poor failure records** make it impossible to train or validate supervised models.
- **Pilot purgatory:** a successful pilot that never scales because the pipeline and work process were not designed for it.

Predictive maintenance is one of the most proven uses of industrial AI. Combined with physics knowledge in a [digital twin](/automation-robotics/digital-twin-explained/) and the large data volumes described in [the five Vs of big data](/ai-data-engineering/big-data-five-vs/), it turns sensor data into fewer breakdowns and lower maintenance cost.

## Key formulas for predictive maintenance

| Quantity | Formula | Symbols and units |
| --- | --- | --- |
| RMS value | x_RMS = √[(1/N) Σ x_i²] | x_i = signal samples (for example mm/s or g), N = number of samples |
| Crest factor | CF = x_peak ÷ x_RMS | dimensionless, rises with impulsive faults |
| Kurtosis | K = [(1/N) Σ (x_i − x̄)⁴] ÷ σ⁴ | x̄ = mean, σ = standard deviation; about 3 for a healthy random signal |
| Cost per failure | C = t_down × c_hour + C_repair | t_down in h, c_hour = production loss per hour |
| Annual saving | S = C_without − (C_caught + C_missed + C_monitoring) | all in currency per year |

## Predictive maintenance interview and viva questions

1. **How does predictive maintenance differ from preventive maintenance?** Preventive maintenance is done at fixed intervals whatever the condition, while predictive maintenance uses measured condition to estimate when failure will occur and schedules work just before it.
2. **Why is anomaly detection usually the first model deployed?** It learns only what normal operation looks like, so it needs no failure history, which most plants do not have when they start.
3. **Why is kurtosis useful for bearing faults?** Early bearing damage produces sharp impacts that make the signal impulsive, and kurtosis rises well above its healthy value of about 3 in response.
4. **What is class imbalance and how is it handled?** Failures are rare compared with normal data, so a naive classifier can ignore them. Careful labelling, resampling or class weighting, and precision and recall based evaluation address it.
5. **What does a remaining useful life model predict?** It is a regression model that estimates the time or cycles left before failure, often by tracking a health indicator or learning from run to failure sequences such as the NASA C-MAPSS dataset.
