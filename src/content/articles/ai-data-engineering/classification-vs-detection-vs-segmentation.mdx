  - q: "Which computer vision task should I use for defect inspection?"
    a: "If you only need a pass or fail decision per part, image classification is enough. If you need to know where each defect is, or count defects, use object detection. <Key title="Short answer">

In **classification vs detection vs segmentation**, the difference is how much the model tells you about an image. **Image classification** gives one label for the whole image ("this is a cat"). **Object detection** finds each object and draws a **bounding box** with a label and confidence score. **Segmentation** labels every **pixel**, giving the exact shape of each object or region. Each step adds detail but also needs more labelling effort and more compute.

</Key>

Computer vision teaches machines to understand images and video. Almost every practical vision system, from a phone camera to a factory inspection line, is built on one of three core tasks. Choosing the right one is the first design decision and drives the data you need, the model you train and how you measure success.

## Image classification

Classification answers the question "what is in this image?" The model outputs a probability for each class, and the highest is the prediction. Variants include **binary** (good or defective), **multi-class** (one of 1000 categories) and **multi-label** (an image can contain both "rust" and "crack").

Models are usually convolutional neural networks (CNNs) such as ResNet and EfficientNet, or vision transformers (ViT). They learn filters that detect edges, then textures, then parts and whole objects, as explained in [how neural networks work](/ai-data-engineering/how-neural-networks-work/).

- **Labels needed:** one class per image.
- **Metrics:** accuracy, precision, recall, F1 score and confusion matrix.
- **Uses:** sorting products, medical image screening, pass or fail inspection, plant disease identification.

## Object detection

Detection answers "what objects are here, and where?" For each object it predicts a class, a confidence score and a bounding box (x, y, width, height). A single image can contain many objects of many classes.

Two families dominate:

- **Two stage detectors** such as Faster R-CNN first propose candidate regions, then classify and refine each one. They are accurate but slower.
- **One stage detectors** such as YOLO, SSD and RetinaNet predict boxes and classes in a single pass, fast enough for real time video. Transformer based detectors such as DETR are also widely used.

Box quality is measured by **intersection over union (IoU)**:

$$
\text{IoU} = \frac{\text{Area of overlap}}{\text{Area of union}}
$$

A prediction usually counts as correct when IoU is at least 0.5 and the class matches. Overall performance is reported as **mean average precision (mAP)**, averaging precision over classes and, in the COCO benchmark, over IoU thresholds from 0.5 to 0.95.

- **Labels needed:** a box and class for each object.
- **Uses:** counting parts on a conveyor, pedestrian detection in vehicles, PPE compliance checks, retail shelf monitoring.

## Image segmentation

Segmentation answers "which pixels belong to what?" The output is a mask the same size as the image.

- **Semantic segmentation** gives each pixel a class (road, car, sky) without separating individual objects. U-Net and DeepLab are classic models.
- **Instance segmentation** separates each object of the same class with its own mask. Mask R-CNN extends Faster R-CNN with a mask branch.
- **Panoptic segmentation** combines both: every pixel gets a class, and countable objects also get an instance identity.

Metrics include pixel accuracy, mean IoU across classes and the Dice coefficient, which is popular in medical imaging.

- **Labels needed:** pixel masks or polygon outlines.
- **Uses:** tumour boundaries in medical scans, drivable area for autonomous vehicles, measuring crack or corrosion area, satellite land use mapping.

## Classification vs detection vs segmentation: comparison

| Feature | Classification | Object detection | Segmentation |
| --- | --- | --- | --- |
| Question answered | What is in the image? | What and where (box)? | What and exactly where (pixels)? |
| Output | Class label and probability | Boxes, classes, scores | Pixel mask per class or instance |
| Labelling effort | Lowest | Medium | Highest |
| Compute cost | Lowest | Medium | Highest |
| Typical models | ResNet, EfficientNet, ViT | YOLO, Faster R-CNN, DETR | U-Net, DeepLab, Mask R-CNN |
| Main metric | Accuracy, F1 | mAP at IoU thresholds | Mean IoU, Dice |
| Industrial example | Good or reject part | Count and locate defects | Measure defect area |

## How to choose

1. **Start with the business question.** Do you need a decision, a location and count, or an exact shape and size?
2. **Pick the simplest task that answers it.** Classification is cheaper to label and runs on modest hardware.
3. **Consider the deployment hardware.** Real time detection on an edge camera may need a small YOLO style model; segmentation at high resolution needs a GPU.
4. **Plan the labelling budget.** Segmentation labels can cost ten times more than classification labels.

Tasks can also be chained: a detector finds each part, then a classifier grades it, or a detector crops a region that a segmentation model measures.

## Practical tips

- Use **transfer learning**: start from a model pre-trained on ImageNet or COCO and fine tune on your images. It needs far less data.
- **Augment** data with flips, rotations, brightness changes and crops so the model copes with real conditions.
- Control the **lighting and optics** in industrial setups; good images beat clever models. See [machine vision components](/automation-robotics/machine-vision-components/) for cameras, lenses and lighting.
- Validate on images from the real production line, not only lab samples.

All three tasks are [supervised learning](/ai-data-engineering/supervised-vs-unsupervised-learning/) problems, so label quality limits model quality. A small, carefully labelled dataset often beats a large, noisy one.
