<Key title="Short answer">

**Big data** is data whose volume, velocity, variety, veracity or value stretch beyond what a single conventional server or database can store and process in the time needed. These five Vs describe its scale, speed, formats, trustworthiness and usefulness, and distributed platforms such as Apache Spark, Kafka, data lakes and cloud warehouses handle it across many machines.

</Key>

Organisations now collect data from websites, apps, machines, sensors, transactions and documents at a scale that traditional databases were never designed for. The term big data describes this challenge. Analyst Doug Laney described the first three Vs in 2001, and veracity and value were added later to capture data quality and purpose.

## The five Vs explained

### 1. Volume

The amount of data, measured in terabytes (TB), petabytes (PB) or more. Large volumes come from web logs, video, high frequency sensors, scientific instruments and transaction records. Storing and scanning this much data requires spreading it across many disks and servers.

### 2. Velocity

The speed at which data is created and must be processed. Some data arrives in daily batches; other data streams continuously, such as card payments that must be checked for fraud within milliseconds, or vibration sensors sampling thousands of times a second. High velocity calls for **stream processing**.

### 3. Variety

The range of data types:

- **Structured:** rows and columns in databases, such as orders and sensor tables.
- **Semi-structured:** JSON, XML and log files with flexible fields.
- **Unstructured:** text documents, emails, images, audio and video.

Combining these requires flexible storage and processing tools, and often machine learning to extract meaning from unstructured data, for example through [computer vision](/ai-data-engineering/classification-vs-detection-vs-segmentation/) or [NLP embeddings](/ai-data-engineering/tokenization-and-embeddings/).

### 4. Veracity

The quality, accuracy and trustworthiness of the data. Sensor drift, missing values, duplicates, biased samples and conflicting sources all reduce veracity. At large scale, small error rates still mean millions of bad records, so automated validation and data lineage are essential.

### 5. Value

The reason to collect data at all. Data has value only if it leads to better decisions: lower costs, higher quality, less downtime or better customer service. Storing everything "just in case" without a use for it costs money and adds risk.

Some authors add more Vs, such as variability (changing meaning or flow rate) and visualisation, but these five are the most widely used.

## Big data platforms and tools

The key idea behind big data platforms is **horizontal scaling**: instead of buying one ever larger server, spread data and work across many ordinary machines, and move the computation to where the data is stored.

### Hadoop

Apache Hadoop, based on Google's papers on its file system and MapReduce (2003 and 2004), made this approach widely available. It has:

- **HDFS:** a distributed file system that splits files into blocks and stores copies on several machines for fault tolerance.
- **MapReduce:** a programming model that processes data in parallel (map) and combines the results (reduce).
- **YARN:** a resource manager that schedules jobs on the cluster.

### Apache Spark

Spark processes data in memory across a cluster and is much faster than MapReduce for multi-step and iterative jobs. It offers SQL, DataFrames, streaming and a machine learning library in one engine, and is the most common big data processing tool today.

### Streaming: Kafka and Flink

**Apache Kafka** is a distributed event log that collects and delivers high velocity data streams reliably between systems. **Apache Flink** and Spark Structured Streaming process those streams in near real time, for example to compute rolling averages or detect anomalies as data arrives.

### Data lakes, warehouses and lakehouses

- **Data lake:** low cost object storage (such as Amazon S3 or Azure Data Lake Storage) holding raw data of any type.
- **Data warehouse:** structured, optimised storage for fast SQL analytics, such as Snowflake, BigQuery or Redshift.
- **Lakehouse:** open table formats such as Delta Lake, Apache Iceberg and Apache Hudi add warehouse features to lake storage.

Data moves into these platforms through [ETL or ELT pipelines](/ai-data-engineering/etl-vs-elt/).

| Need | Typical tools |
| --- | --- |
| Distributed storage | HDFS, Amazon S3, Azure Data Lake Storage, Google Cloud Storage |
| Batch processing | Apache Spark, Hadoop MapReduce |
| Stream ingestion | Apache Kafka, Amazon Kinesis, Azure Event Hubs |
| Stream processing | Apache Flink, Spark Structured Streaming |
| SQL analytics | Snowflake, BigQuery, Redshift, Databricks SQL, Trino |
| Time series and IoT | InfluxDB, TimescaleDB, plant historians |

## Big data in industry

Industrial data has its own character. Signals are mostly time series, sampled at fixed rates, tagged by instrument and often stored for decades for regulatory and engineering reasons. Context matters as much as the values: a reading means little without knowing the unit, the operating mode and whether the instrument was in calibration.


In manufacturing and process plants, big data comes from historians, SCADA systems, quality labs and maintenance records. Common uses include [predictive maintenance](/ai-data-engineering/predictive-maintenance-machine-learning/), energy optimisation, yield improvement and [digital twins](/automation-robotics/digital-twin-explained/).

The five Vs are a useful checklist when planning any data project: estimate the volume and velocity, list the varieties, plan for veracity, and above all define the value before building the platform.

## Big data interview and viva questions

1. **What are the five Vs of big data?** Volume, velocity, variety, veracity and value. Doug Laney described the first three in 2001, and veracity and value were added later to capture data quality and purpose.
2. **What is horizontal scaling?** It means spreading data and work across many ordinary machines instead of buying one ever larger server, and moving the computation to where the data is stored.
3. **Why is Spark faster than MapReduce for iterative jobs?** MapReduce writes intermediate results to disk between every step, while Spark keeps working data in memory across steps where possible.
4. **What is the difference between a data lake and a data warehouse?** A data lake is low cost object storage holding raw data of any type, while a data warehouse is structured, optimised storage for fast SQL analytics.
5. **Why does veracity matter more as volume grows?** At large scale even small error rates mean millions of bad records, so automated validation and data lineage become essential.
