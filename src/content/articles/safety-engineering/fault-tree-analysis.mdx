<Key title="Short answer">

**Fault tree analysis** (FTA) is a top-down, deductive method that starts from one undesired system event and breaks it into the combinations of component failures, human errors and external events that can cause it. Events are linked by **AND** and **OR** logic gates, and the tree gives **minimal cut sets** and the top event probability.

</Key>

Fault tree analysis is one of the most widely used tools in system safety and reliability engineering. It answers a precise question: what has to go wrong, and in what combination, for this specific accident or failure to happen? The method was developed in 1961 and 1962 at Bell Telephone Laboratories for the US Air Force Minuteman launch control system, then adopted by Boeing, the nuclear industry and NASA. Today it is standardised in IEC 61025 and used in process plants, aircraft, rail signalling, medical devices and functional safety studies.

## What fault tree analysis does

FTA is **deductive**: it reasons from an effect back to its causes. The analyst picks one **top event**, such as "loss of cooling to the reactor" or "aircraft fails to lower landing gear", and asks what immediate causes could produce it. Each cause is then broken down again until the analysis reaches **basic events**, which are failures that need no further development, such as a pump failing to start or a valve sticking closed.

The result is a logic diagram that shows:

- every combination of failures that leads to the top event (the **cut sets**),
- which failures are **single points of failure**,
- where **redundancy** really protects the system and where it does not,
- and, with failure data, the **probability** or frequency of the top event.

This makes FTA complementary to [FMEA](/safety-engineering/fmea-explained/). FMEA works bottom-up from each failure mode and covers many effects, while FTA focuses on one top event and handles multiple failures acting together. Hazards for the top event usually come from a [HAZOP study](/safety-engineering/hazop-study/) or a preliminary hazard analysis.

## Fault tree symbols and gates

IEC 61025 and the NRC Fault Tree Handbook (NUREG-0492) use a common set of symbols.

### Event symbols

- **Rectangle (intermediate event):** a fault that results from other events through a gate below it. The top event is drawn as a rectangle.
- **Circle (basic event):** a basic initiating failure with known or estimated probability data.
- **Diamond (undeveloped event):** an event not developed further, because of lack of information or because it is judged unimportant.
- **House (external event):** an event that is normally expected to occur or not occur, used as a switch to model different conditions.
- **Triangle (transfer):** shows that the tree continues on another page.

### Logic gates

- **OR gate:** the output event occurs if **at least one** input event occurs.
- **AND gate:** the output event occurs only if **all** input events occur. AND gates model redundancy.
- **Voting gate (k out of n):** the output occurs if at least k of the n inputs occur, for example a 2 out of 3 trip system.
- **Inhibit gate:** the output occurs when the input occurs and a stated condition is satisfied.
- **Priority AND gate:** the output occurs only if the inputs occur in a specified order. It is one of the dynamic gates described in the NASA handbook.

## How to perform fault tree analysis step by step

The NASA and NRC handbooks describe broadly the same procedure.

1. **Define the system and its boundaries:** drawings, operating modes, interfaces, and what is inside and outside the analysis.
2. **Define the top event precisely:** one undesired state, with the system condition and time, for example "no water at the sprinkler header within 30 s of demand".
3. **Develop the tree:** for each event, ask for the immediate, necessary and sufficient causes and connect them with the correct gate. Stop at basic events with available data.
4. **Find the minimal cut sets** using Boolean algebra or software.
5. **Quantify:** assign probabilities or failure rates to basic events and calculate the top event probability.
6. **Rank importance:** identify which basic events contribute most.
7. **Act and document:** propose design or maintenance changes and record assumptions.

A useful rule from NUREG-0492 is the "immediate cause" concept: move down the tree in small steps rather than jumping straight to component failures, so that no cause path is missed.

## Minimal cut sets and Boolean algebra

A fault tree is a Boolean expression. An OR gate is a logical sum (A + B) and an AND gate is a logical product (A · B). Simplifying the expression with Boolean rules, such as A + A · B = A, gives the **minimal cut sets**.

For the tree in the figure, the top event T is:

$$
T = E_1 + E_2 \cdot E_3 + E_4
$$

So the minimal cut sets are E1, E4 and the pair E2 and E3. E1 and E4 are first order cut sets, meaning single points of failure. The pump pair is a second order cut set, because both pumps must fail. In general, low order cut sets deserve the most attention.

A major caution is **common cause failure**. Two identical pumps in the same room, fed from the same supply and maintained by the same procedure, may fail together. The handbooks recommend modelling common cause failures explicitly, otherwise AND gates can make redundancy look far better than it is.

## Quantitative fault tree analysis

If basic events are independent, gate probabilities follow from probability rules:

$$
P_{AND} = \prod_{i=1}^{n} P_i
$$

$$
P_{OR} = 1 - \prod_{i=1}^{n} (1 - P_i)
$$

When all probabilities are small, the **rare event approximation** sums the cut set probabilities, which gives a slightly conservative (higher) result:

$$
P_T \approx \sum_{j} P(C_j)
$$

For a non repairable component with constant failure rate λ, the probability of failure by time t is:

$$
q(t) = 1 - e^{-\lambda t} \approx \lambda t
$$

The approximation holds when λt is small. Failure rate concepts are covered in [MTBF, MTTR and availability](/safety-engineering/mtbf-mttr-availability/).

## Importance measures

Once quantified, the tree shows where improvement pays off. The **Fussell-Vesely importance** of a basic event is the fraction of the top event probability coming from cut sets that contain it, as calculated for the power supply above. **Birnbaum importance** is the change in top event probability per unit change in the basic event probability. Both are described in the NASA handbook and in Rausand's System Reliability Theory.

## Key formulas for fault tree analysis

| Quantity | Formula | Symbols and units |
| --- | --- | --- |
| AND gate probability | P = P1 × P2 × ... × Pn | Pi = probability of independent input events, dimensionless |
| OR gate probability | P = 1 − (1 − P1)(1 − P2)...(1 − Pn) | Exact for independent inputs |
| Rare event approximation | P_T ≈ sum of P(Cj) | Cj = minimal cut sets; valid when probabilities are small |
| Component failure probability | q(t) = 1 − e^(−λt) ≈ λt | λ = failure rate per hour, t = time in hours |
| Fussell-Vesely importance | FV_i = P(cut sets containing i) ÷ P_T | Fraction of top event probability, dimensionless |

## Advantages and limitations

**Advantages**

- Gives a clear visual picture of how failures combine.
- Finds single points of failure and weak redundancy.
- Supports both qualitative and quantitative analysis.
- Fits naturally with [layer of protection analysis](/safety-engineering/lopa-explained/) and [safety integrity level](/safety-engineering/safety-integrity-level/) verification.

**Limitations**

- Covers one top event per tree, so many trees may be needed.
- Large trees need software, and results depend on the analyst's skill and data quality.
- Standard static gates do not capture timing or sequence well; dynamic gates or Markov models are needed for that.
- Human error and common cause failures are hard to quantify.

FTA is also used after incidents, alongside [root cause analysis methods](/safety-engineering/root-cause-analysis-methods/), to show which combination of failures actually occurred.

## Fault tree analysis interview and viva questions

1. **Why is fault tree analysis called a deductive method?** It starts from a defined undesired top event and reasons downward to the causes that could produce it, rather than starting from component failures.
2. **What is the difference between an AND gate and an OR gate in a fault tree?** An OR gate output occurs if any one input occurs, while an AND gate output occurs only if all inputs occur together, which is how redundancy is modelled.
3. **What does a first order minimal cut set indicate?** It is a single basic event that alone causes the top event, so it is a single point of failure and usually a priority for design improvement.
4. **When is the rare event approximation acceptable?** When basic event probabilities are small, so summing cut set probabilities gives a result close to the exact value and slightly on the conservative side.
5. **Why must common cause failures be considered in an AND gate?** Redundant items that share causes may fail together, so multiplying their probabilities as independent events can greatly underestimate the real risk.
