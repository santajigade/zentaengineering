<Key title="Short answer">

**Firewalls explained** simply: a firewall is a device or software that sits between networks and **allows or blocks traffic based on rules**. Rules match addresses, ports, protocols and, in advanced firewalls, applications and users. Main types are **packet filtering**, **stateful inspection**, **proxy (application level)** and **next generation firewalls (NGFW)** that add intrusion prevention and application awareness. Good practice is **default deny**: block everything, then allow only the traffic that is needed.

</Key>

Every network connected to the internet, and every industrial control network connected to an office network, needs a controlled boundary. A firewall is that boundary. Like a security guard at a gate, it checks every connection against a list of what is allowed.

## How a firewall works

A firewall inspects traffic passing between its interfaces and compares it with an ordered **rule set** (also called an access control list or policy). Each rule typically specifies:

- Source and destination IP address or network
- Protocol (TCP, UDP, ICMP)
- Destination port, which identifies the service (for example TCP 443 for HTTPS, TCP 502 for Modbus TCP)
- Action: allow, deny or drop, and whether to log

Rules are checked from the top; the **first match** decides. The last rule is normally an implicit or explicit **deny all**, so anything not specifically allowed is blocked.

## Types of firewalls

### Packet filtering (stateless)

The simplest type checks each packet's header (addresses, ports, protocol) against the rules, with no memory of earlier packets. It is fast and cheap, often built into routers as access lists, but it cannot tell whether a packet belongs to a legitimate connection, so return traffic needs separate, broad rules.

### Stateful inspection

A stateful firewall keeps a **connection table**. When an allowed connection starts, for example a TCP handshake from inside to a web server, it records the session and automatically permits the matching return traffic. Packets that do not belong to a known session are dropped. This is the baseline for all modern firewalls.

### Proxy or application level gateway

A proxy firewall terminates the connection itself and opens a new one to the destination on the client's behalf. It can inspect full application content, such as HTTP requests, and hide internal addresses completely, at the cost of more processing and latency.

### Next generation firewall (NGFW)

An NGFW adds:

- **Application identification**, so rules can say "allow Microsoft Teams" rather than just ports.
- **Intrusion prevention (IPS)** using signatures of known attacks.
- **User identity** awareness linked to directory services.
- **TLS inspection**, malware filtering and threat intelligence feeds.

**Industrial firewalls** go further with **deep packet inspection of OT protocols**, for example allowing Modbus reads but blocking writes, or only permitting specific function codes.

### Host based and cloud firewalls

Firewalls also run as software on individual computers (Windows Defender Firewall, iptables or nftables on Linux) and as cloud services such as security groups and web application firewalls.

## Firewall types compared

| Type | Inspects | Strength | Limitation |
| --- | --- | --- | --- |
| Packet filter | Headers of each packet | Fast, simple | No connection awareness |
| Stateful | Headers plus session state | Secure default, efficient | Limited content checks |
| Proxy | Full application content | Deep inspection, hides hosts | Slower, protocol specific |
| NGFW | Applications, users, threats | Rich policy and IPS | Cost and complexity |
| Industrial DPI | OT protocol commands | Blocks unsafe commands | Needs protocol knowledge to configure |

## Firewalls explained in the plant: zones and conduits

Industrial networks are usually divided into levels, following the Purdue reference model: field devices and PLCs at the bottom, supervisory SCADA and HMIs above them, site operations and historians above that, and the business network at the top. Firewalls sit between these levels so that a problem in one zone, such as malware on an office PC, cannot spread directly to the controllers. IEC 62443 calls each protected group a **zone** and each controlled path between zones a **conduit**, and sets target security levels for both.

A common pattern places two firewalls, or one firewall with three interfaces, around an industrial DMZ. The business network can reach only servers in the DMZ, and the control network pushes data out to those servers. No connection ever passes straight through from top to bottom. Remote access for vendors goes through a jump server in the DMZ with multi-factor authentication and session recording, and is enabled only when needed.

## Firewall best practices

- **Default deny** and allow only documented, required traffic.
- Be **specific**: avoid "any" in source, destination or port where possible.
- **Segment** networks into zones by trust level, with firewalls at the conduits between them, following IEC 62443 zones and conduits.
- Place outward facing services in a **DMZ**; never allow direct connections from the internet to control systems.
- **Log and monitor** denied and allowed traffic; alerts reveal scans and misconfigurations.
- **Review rules** periodically and remove unused ones.
- Keep firmware **patched**, and protect the firewall's own management interface.
- Remember that a firewall is one layer; combine it with patching, strong authentication and backups.

Firewalls work mainly at layers 3 and 4 of the [OSI model](/telecommunication-engineering/osi-vs-tcp-ip-model/), with NGFWs reaching layer 7. They usually sit where a [router](/telecommunication-engineering/router-vs-switch/) connects zones. For plant networks, see [SCADA system architecture](/automation-robotics/scada-system-architecture/) and [DCS architecture](/automation-robotics/dcs-architecture/), and the [industrial communication articles on Instrumentation Blog](https://www.instrumentationblog.in/category/automation/communication/).
