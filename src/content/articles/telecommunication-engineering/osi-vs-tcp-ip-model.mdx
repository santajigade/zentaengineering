<Key title="Short answer">

In **OSI vs TCP/IP model** comparisons, both describe how data moves through a network in layers. The **OSI model** has **seven layers**: physical, data link, network, transport, session, presentation and application. The **TCP/IP model** has **four layers**: link (network access), internet, transport and application. OSI is a reference model used for teaching and troubleshooting; TCP/IP is the protocol suite the internet and most industrial Ethernet networks actually run on.

</Key>

Network communication is complex: electrical signals, addresses, error checks, retransmissions and application formats all have to work together. Layered models split this work so that each layer handles one job and relies on the layer below. That separation is why a web browser does not care whether the data travels over fibre, copper or Wi-Fi.

## The OSI model: seven layers

The Open Systems Interconnection model was published by ISO in 1984 (ISO/IEC 7498). From bottom to top:

1. **Physical:** transmits raw bits as electrical, optical or radio signals. Cables, connectors, voltage levels, [fibre optics](/telecommunication-engineering/single-mode-vs-multimode-fiber/), hubs and repeaters.
2. **Data link:** frames bits into frames, adds MAC addresses and an error check (CRC), and controls access to the medium. Ethernet, Wi-Fi MAC, PPP and switches.
3. **Network:** logical addressing and routing between networks. IP, ICMP and routers.
4. **Transport:** end to end delivery between applications, using port numbers. TCP gives reliable, ordered delivery; UDP gives fast, connectionless delivery.
5. **Session:** opens, manages and closes sessions between applications.
6. **Presentation:** data formats, encoding, compression and encryption, such as TLS and character encoding.
7. **Application:** the protocols applications use directly: HTTP, DNS, SMTP, FTP, Modbus TCP and OPC UA.

A common memory aid from layer 1 upwards is "Please Do Not Throw Sausage Pizza Away".

## The TCP/IP model: four layers

The TCP/IP model grew out of ARPANET research in the 1970s and is defined in IETF documents such as RFC 1122. It is practical rather than theoretical, built around protocols that already worked:

1. **Link (network access):** combines OSI physical and data link. Ethernet, Wi-Fi, ARP.
2. **Internet:** IP addressing and routing, matching OSI layer 3.
3. **Transport:** TCP and UDP, matching OSI layer 4.
4. **Application:** combines OSI session, presentation and application. Applications handle their own formatting and sessions, for example HTTP over TLS.

Some textbooks show a five layer hybrid that keeps physical and data link separate, which is convenient for teaching.

## Encapsulation: how data moves down and up the layers

When an application sends data, each layer adds its own header in front of the data it receives from above. This is **encapsulation**:

- The application produces a message, such as an HTTP request.
- The transport layer adds a TCP header with source and destination ports, forming a **segment**.
- The network layer adds an IP header with source and destination IP addresses, forming a **packet**.
- The data link layer adds an Ethernet header with MAC addresses and a trailer with a CRC, forming a **frame**.
- The physical layer sends the frame as bits.

The receiver reverses the process, each layer stripping its header and passing the payload up. Routers along the way only open the frame up to layer 3 to read the IP address; switches only look at layer 2. How these devices differ is covered in [router vs switch](/telecommunication-engineering/router-vs-switch/).

## OSI vs TCP/IP model: comparison

| Feature | OSI model | TCP/IP model |
| --- | --- | --- |
| Number of layers | 7 | 4 (5 in some texts) |
| Developed by | ISO, published 1984 | US DoD research, IETF standards |
| Approach | Reference model first, protocols later | Protocols first, model describes them |
| Session and presentation | Separate layers | Part of the application layer |
| Physical and data link | Separate layers | Combined into link layer |
| Use today | Teaching, troubleshooting vocabulary | Internet and most real networks |
| Transport | Connection oriented and connectionless defined | TCP (reliable) and UDP (connectionless) |

## Why layered models matter

- **Troubleshooting:** working bottom up, layer by layer, quickly narrows down faults, as in the example above.
- **Interoperability:** vendors can build products for one layer that work with products from others at other layers.
- **Independent change:** Wi-Fi can replace Ethernet at the link layer without changing TCP or HTTP.
- **Shared vocabulary:** terms such as layer 2 switch, layer 3 routing and layer 7 firewall come from the OSI model.

## Industrial networks and the layers

Industrial protocols fit the same structure. Modbus TCP, EtherNet/IP and OPC UA sit at the application layer on top of TCP or UDP and IP. PROFINET real time traffic skips IP and runs directly over Ethernet for speed. Serial fieldbuses such as Modbus RTU over RS-485 use only the physical, data link and application layers, as explained in [Modbus RTU vs TCP](/automation-robotics/modbus-rtu-vs-tcp/). Layer 3 addresses, subnet masks and prefixes, which routers use to forward packets between networks, are covered in [IP addressing and subnetting](/telecommunication-engineering/ip-addressing-and-subnetting/).

Understanding both models makes it easier to design, secure and troubleshoot any network, from an office LAN to a plant control system or a web service using [HTTP](/computer-science/how-http-works/).
