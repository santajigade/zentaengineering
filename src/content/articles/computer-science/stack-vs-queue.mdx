  - q: "Can a queue be built from two stacks?"
    a: "Yes. Push new items onto an input stack. To dequeue, pop from an output stack; when the output stack is empty, pop every item from the input stack and push it onto the output stack, which reverses the order. Each item is moved at most once, so the amortised cost per operation is constant."
  - q: "Is a priority queue a queue?"
    a: "It shares the queue interface of inserting and removing items, but it does not follow FIFO order. It always removes the item with the highest priority. It is usually built on a binary heap, where insert and remove take logarithmic time."

    a: "A fixed size stack cannot accept more items once it is full. In a running program, the call stack has a limited size, and very deep or infinite recursion fills it. The program then stops with a stack overflow error, such as RecursionError in Python or StackOverflowError in Java."

<Key title="Short answer">

In **stack vs queue**, the difference is the order in which items leave. A **stack** is last in, first out (LIFO): items are added and removed at the same end, the top. A **queue** is first in, first out (FIFO): items join at the rear and leave from the front. Both support their main operations in constant time; stacks suit nested and backtracking tasks, queues suit fair, in-order processing.

</Key>

Stacks and queues are two of the simplest and most widely used data structures. Both hold a collection of items and restrict which item can be removed next. That restriction is what makes them useful: it matches the natural order of many problems, from function calls and undo histories to print jobs and network packets. This guide compares them side by side, shows how they are implemented, and explains when to use each.

## How a stack and a queue work

A **stack** works like a pile of plates. You put a plate on top (push) and take the top plate off (pop). The plate removed is always the most recently added one.

A **queue** works like a line at a ticket counter. People join at the back (enqueue) and are served from the front (dequeue). The person served is always the one who has waited longest.

## Stack vs queue comparison table

| Feature | Stack | Queue |
| --- | --- | --- |
| Order | LIFO: last in, first out | FIFO: first in, first out |
| Insert | push (at top) | enqueue (at rear) |
| Remove | pop (from top) | dequeue (from front) |
| Look without removing | peek or top | peek or front |
| Ends used | One end | Two ends |
| Time for insert and remove | O(1) | O(1) |
| Typical array implementation | Array with a top index | Circular buffer with front and rear indices |
| Classic algorithm | Depth-first search | Breadth-first search |
| Typical uses | Function calls, undo, parsing, backtracking | Scheduling, buffering, message passing |

All the main operations run in constant time, O(1), when the structure is implemented correctly. The meaning of this notation is explained in [Big O notation explained with examples](/computer-science/big-o-notation/).

## Differences explained

### Access order

The only real difference between the two structures is which item leaves next. A stack reverses order: push A, B, C and you pop C, B, A. A queue preserves order: enqueue A, B, C and you dequeue A, B, C. Every use case follows from this property.

### Implementation

Both can be built on an array or a linked list. The trade-offs between those two storage methods are covered in [arrays vs linked lists](/computer-science/arrays-vs-linked-lists/).

- **Stack on an array:** keep an index to the top. Push writes at top and increments it; pop decrements it and reads. A dynamic array grows when full, giving amortised O(1) push.
- **Stack on a linked list:** push and pop at the head node.
- **Queue on an array:** a naive array that removes from index 0 must shift every remaining element, which is O(n). A **circular buffer** avoids this. It keeps front and rear indices that wrap around to the start of the array using the modulo operation.
- **Queue on a linked list:** keep pointers to both the head (front) and tail (rear) nodes, so both operations are O(1).

### In standard libraries

- **Python:** a list works as a stack with append and pop. For a queue, the documentation recommends collections.deque, because list.pop(0) and list.insert(0, x) are O(n), while deque supports fast appends and pops at both ends.
- **Java:** the Java API documentation states that the Deque interface and its implementations (such as ArrayDeque) provide a more complete set of LIFO stack operations and should be used in preference to the older Stack class. Queue is an interface implemented by ArrayDeque and LinkedList.
- **C++:** std::stack and std::queue are container adaptors, by default built on std::deque.

## Related structures

- **Deque (double-ended queue):** insert and remove at both ends, so it can act as either a stack or a queue.
- **Circular queue:** a fixed capacity queue on a circular buffer, common in device drivers and embedded systems.
- **Priority queue:** removes the highest priority item rather than the oldest; usually a binary heap with O(log n) insert and remove.

## When to use a stack vs queue

Use a **stack** when the most recent item must be handled first:

- **Function calls:** the call stack stores return addresses and local variables; the most recent call returns first. Each [process or thread](/computer-science/process-vs-thread/) has its own call stack.
- **Undo and back navigation:** editors and browsers push each action or page and pop to go back.
- **Parsing and expression evaluation:** checking balanced brackets, converting infix to postfix, and evaluating postfix expressions, as in the example.
- **Backtracking and depth-first search:** maze solving, puzzle solvers and graph traversal go as deep as possible, then pop back.

Use a **queue** when items must be handled in arrival order:

- **Scheduling:** operating system ready queues, print spoolers and job queues.
- **Buffering:** keyboard input, serial communication and audio streams use circular buffers between a producer and a consumer running at different speeds.
- **Breadth-first search:** exploring a graph level by level, which finds the shortest path in an unweighted graph.
- **Messaging:** message brokers and task queues pass work between services in order.

## Common mistakes

- Using a Python list as a queue with pop(0), which becomes slow for large queues.
- Popping from an empty stack or dequeuing from an empty queue without a check.
- Forgetting the modulo wrap in a circular buffer, which writes past the end of the array.
- Writing deep recursion without considering the call stack limit; an explicit stack can replace recursion.
