<Key title="Short answer">

In **arrays vs linked lists**, an array stores elements side by side in one memory block, giving constant time access by index but costly middle insertions. A linked list chains separate nodes with pointers, so inserting at a known node is fast but reaching the i-th element needs a walk. Arrays are usually faster thanks to cache locality.

</Key>

Arrays and linked lists are the two basic ways to store a sequence of items. Almost every other data structure, from stacks and queues to hash tables and graphs, is built on one or both. Choosing between them depends on which operations a program performs most often and how much memory it can spare.

### Arrays

An array reserves one contiguous block for n elements of equal size. The address of element i is the base address plus i times the element size, so the processor reaches any element directly. Static arrays have a fixed size; **dynamic arrays** (Python list, Java ArrayList, C++ vector) grow by allocating a bigger block and copying when full.

### Linked lists

A linked list is a chain of **nodes**. Each node holds a value and a pointer (reference) to the next node. A program keeps a pointer to the first node, the **head**. Variants include:

- **Singly linked list:** each node points to the next.
- **Doubly linked list:** each node also points to the previous node, allowing backward traversal and easy removal of a given node.
- **Circular linked list:** the last node points back to the first.

## Arrays vs linked lists: operation costs

| Operation | Array (dynamic) | Singly linked list |
| --- | --- | --- |
| Access element by index | O(1) | O(n) |
| Search for a value (unsorted) | O(n) | O(n) |
| Insert or delete at the end | Amortised O(1) | O(1) with a tail pointer (delete needs O(n) unless doubly linked) |
| Insert or delete at the front | O(n), elements shift | O(1) |
| Insert or delete in the middle, position known | O(n), elements shift | O(1) once the node is found |
| Binary search on sorted data | O(log n) | Not practical |
| Extra memory per element | None (some spare capacity) | One or two pointers |

The notation is explained in [Big O notation](/computer-science/big-o-notation/). The table shows a trade-off: arrays win at reading by position, linked lists win at changing the structure in place.

## Cache behaviour: why arrays are often faster

Modern processors load memory into caches in lines of typically 64 bytes. Walking through an array touches consecutive addresses, so each cache line brings in several useful elements and the hardware prefetcher can predict what comes next. Linked list nodes are allocated separately and may be scattered, so each step can be a cache miss that costs far more time than the arithmetic itself. As a result, even operations with the same Big O cost, such as a linear search, usually run noticeably faster on arrays. Memory hierarchy is discussed further in [Von Neumann vs Harvard architecture](/computer-science/von-neumann-vs-harvard-architecture/).

## When to use each

**Use an array (or dynamic array) when:**

- Elements are accessed by index or iterated in order.
- The data is mostly appended at the end and read many times.
- You need sorting, binary search or tight memory use.
- Performance matters and cache friendliness counts, which is most of the time.

**Use a linked list when:**

- You frequently insert or remove items in the middle and already hold references to those positions, as in LRU caches combined with a hash map.
- Elements must never move in memory because other structures point to them.
- You need constant time splicing of whole lists, as in some memory allocators and operating system kernels, for example the ready queues used in [process and thread scheduling](/computer-science/process-vs-thread/).

## Arrays and linked lists in popular languages

- **Python:** the built-in list is a dynamic array of references; collections.deque is a linked structure of blocks with fast appends and pops at both ends.
- **Java:** ArrayList is a dynamic array; LinkedList is a doubly linked list. ArrayList is the usual default.
- **C++:** std::vector is a dynamic array, std::list is a doubly linked list and std::forward_list a singly linked one. std::vector is recommended as the default container.
- **C:** arrays are built in; linked lists are written by hand with structs and pointers.
- **JavaScript:** arrays are dynamic and engines optimise them heavily; linked lists are rarely needed.

In most languages the standard advice is the same: start with the dynamic array and switch only when profiling shows a real need.

When a program needs both fast indexing and cheap insertion, hybrid structures such as gap buffers, ropes or skip lists are worth considering.

## Arrays vs linked lists interview and viva questions

1. **Why is array indexing O(1)?** Elements are contiguous and equal in size, so the address of element i is the base address plus i times the element size, computed in one step.
2. **When is linked list insertion O(1)?** Only when a reference to the insertion point, such as the head or a node found earlier, is already held; finding the position first takes O(n).
3. **Why are arrays usually faster than linked lists for a linear search?** Consecutive array elements share cache lines and are prefetched, while scattered list nodes can cause a cache miss at every step.
4. **What advantage does a doubly linked list have over a singly linked list?** Each node also points to the previous node, allowing backward traversal and easy removal of a given node.
5. **How does a dynamic array achieve amortised O(1) appends?** When full it allocates a larger block, usually a constant multiple of the old size, and copies the elements, so the occasional copy cost is spread over many appends.

## Related structures

- **Stacks and queues** can be built on either; arrays (ring buffers) are common in practice.
- **Hash tables** use arrays of buckets, sometimes with linked lists for collisions.
- **Trees and graphs** generalise linked lists with several pointers per node.
- **Database tables** store rows in pages and use index structures such as B-trees; see [database normalization](/computer-science/database-normalization/) for how tables are designed.

The right choice is the one that makes the program's most common operations cheap, and when in doubt, measure.
